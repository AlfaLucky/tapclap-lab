## Покрытие 42 проверками

**Сервер и данные — 30 проверок:** авторизация чтения/записи, HttpOnly/SameSite/Secure,
выход и отзыв сессии, блокировка чужого Origin, ограничение попыток входа,
публичный и закрытый режимы, пути файлов и защита spec.json, HTTP Range,
повтор только failed, отмена ожидающего задания, FIFO и конкурентное получение,
ёмкость очереди, восстановление после перезапуска, расписание и UTC+4,
сохранение единственного пропущенного запуска после простоя, пауза расписания,
инкрементальные события, разграничение профилей в статистике, исключение skipped,
валидация сценариев, PNG и drag, экранирование отчёта, отмена активного subprocess,
обработка его аварии, считывание последних событий после выхода и очистка материалов.

**Браузерная семантика — 12 проверок:** HTTP 503 не считается успехом,
Canvas означает только видимость, обрезание Canvas и горизонтальная прокрутка
дают ошибку, отсутствие ready/baseline даёт skipped до навигации, JS/resource
ошибки приводят к failed, отмена обнаруживается, выбирается точный вариант
шаблона, query-секреты удаляются из URL диагностики, JUnit содержит skipped/errors.
Эти проверки используют тестовые объекты Playwright, не реальную игру.

Ни один результат тестового subprocess не попадает в поставляемую базу:
приложение начинает с пустой историей. Исходники fake worker находятся только в tests/.

## Обязательная проверка после развёртывания

1. Docker собирается, `/healthz` отвечает 200, данные пишутся в Volume `/data`.
2. Без входа доступны отчёты, запуск даёт 401. После входа запуск доступен.
3. Реальные HTTP и Canvas проверки получают настоящий результат стенда.
4. В экране есть реальные кадры, затем работают MJPEG, WebM и перемотка записи.
5. Остановка завершает браузер, следующий прогон берётся из очереди.
6. Из реального кадра сохранён шаблон готового экрана; ready действительно
   находит его, а отрицательный/чужой шаблон не проходит.
7. Создан и выполнен хотя бы один игровой сценарий с проверкой результата.
8. После redeploy история и шаблоны сохранены, активный прогон помечен interrupted.
9. Расписание создаёт один запуск в ожидаемое время и соблюдает паузу.
10. Проверены реальное потребление CPU/RAM, расход на видео и лимиты расходов Railway.

Браузерные и Docker-проверки требуют доступного окружения исполнения.
Для ручного живого smoke предусмотрен workflow `.github/workflows/live-smoke.yml`.
